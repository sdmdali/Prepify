## Password reset implementation update (2026-10-30)

Implemented a complete Resend-backed password-reset workflow:

- Added `POST /api/auth/forgot-password` and `POST /api/auth/reset-password`.
- Added additive migration `002_password_reset_tokens.sql`.
- Reset tokens use 32 bytes of cryptographic randomness; only SHA-256 hashes are stored.
- Tokens expire after 15 minutes and are invalidated after use; issuing a new token invalidates prior active tokens for that account.
- Added per-IP rate limiting and a per-account hourly request cap.
- Unknown/inactive email addresses receive the same generic response as known addresses.
- Added forgot-password and reset-password frontend pages and connected the existing login link.
- Resend is called through Node.js built-in `fetch`; no additional npm dependency is required.
- Added `RESEND_API_KEY` and `RESEND_FROM_EMAIL` configuration documentation.
